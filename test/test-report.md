# 分布式文件存储系统 —— 极限测试报告

> 生成时间：2026-09-25 00:42:19
> 测试方式：VM 本地单机，ZooKeeper 2181 + MySQL 3306；动态发现用 10 节点，规模测试用 3 节点 + 1 个元数据服务
> 测试脚本：`test/integration/run_new_tests.sh`（每个测试结束后还原状态再做下一个；极限测试循序渐进、只取最大成功规模）
> 说明：规模测试降为 3 节点以适配 2GB VM（10 节点 + ZK 并发会内存耗尽致 ZK 崩溃）；「最大成功规模」受测试环境内存封顶，非系统容量上限。

## 1. RPC 调用延迟（直连 FriendService，短连接）

口径：单次 RPC 往返 = TCP 建连 + 请求序列化 + 网络往返 + 响应反序列化（含握手/挥手）。

```
RPC_LATENCY samples=10000 failed=0 avg=207.69us median=166.15us p99=568.80us
```

## 2. 存储节点动态发现（10 节点）

- meta 后台轮询 ZooKeeper 临时节点，实测发现节点数 = **10**。

## 3. 循环上传极限（3 节点）

- 每文件 **1MB（1 块）**，次数循序 3 5，**最大 100% 成功规模 = 5 次**，平均 **29.55 ms/次**。

## 4. 大文件极限（3 节点）

- 大小循序 4 8 MB，**最大成功大小 = 8 MB**，下载 md5 与源文件一致（96995b58d4cbf6aaa9041b4f00c7f6ae），吞吐 47.62 MB/s。

## 5. resume 回填建议（手动修改版 5 条）

1. RPC 框架层：单次 RPC 往返延迟 ~207.69µs（本地回环短连接实测，中位 166.15µs / P99 568.80µs）。
2. 元数据服务：循环上传 1MB 文件 5 次成功率 100%（实测）。
3. 存储服务：逐块 MD5 校验（4MB 块）；单文件 8MB 大文件分块流式读写（实测）。
4. 数据分布优化：约 1/N（理论值，不改）。
5. 传输效率优化：连接建立次数从块数降至节点数（会话复用，1GB 文件 256 块→3 连接）；吞吐 47.62 MB/s（端到端实测）。
